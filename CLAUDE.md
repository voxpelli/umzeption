# CLAUDE.md — Project Intelligence for umzeption

## Project Overview

Framework-agnostic modular database migrations built on [umzug](https://github.com/sequelize/umzug). npm workspaces monorepo with two packages:

- **`packages/umzeption`** — core: dependency resolution, migration lookup, schema helpers, storage base
- **`packages/umzeption-pg`** — PostgreSQL adapter: pg context, advisory locks, SQL parsing, pg storage

## Critical Rules

### Versioning & Releases
- **NEVER** bump version numbers manually in `package.json` — versions are managed by [Release Please](https://github.com/googleapis/release-please) via conventional commits
- **NEVER** edit `CHANGELOG.md` manually — it is auto-generated by Release Please
- Commit messages must follow conventional commits: `feat:`, `fix:`, `refactor:`, etc.
- Packages are versioned independently (see `.github/release-please/config.json`)

### Language & Type System
- Source files are **plain JavaScript** (`.js`) with **JSDoc type annotations**
- TypeScript is used **only** for type-checking (`tsc`) and `.d.ts` generation — never write `.ts` source files
- Module format: **ESM** (`"type": "module"` everywhere). Use `import`/`export`, not `require`
- Hand-authored type declaration files must use the naming pattern `*-types.d.ts` (e.g., `pg-types.d.ts`). The clean script deletes `*.d.ts` files but preserves `*-types.d.ts`

### CI Checks (all must pass)
- `check:tsc` — TypeScript compilation
- `check:lint` — ESLint with `@voxpelli/eslint-config` (0 errors required, warnings are OK)
- `check:knip` — unused exports/dependencies detection
- `check:type-coverage` — strict mode, ≥99% coverage required (currently 100%)
- `check:installed-check` — verifies package.json dependencies match actual usage
- `test:node` — Node.js built-in test runner (`node:test`) with c8 coverage

## Architecture Patterns

### Module Augmentation (Context Registry)
The core `DefineUmzeptionContexts` interface is extensible. Adapter packages add their context type via TypeScript module augmentation in their `*-types.d.ts`:
```ts
declare module 'umzeption' {
  interface DefineUmzeptionContexts {
    pg: UmzeptionPgContext;
  }
}
```
Simply importing `umzeption-pg` activates the `pg` context type project-wide.

### Schema Installer Registry
`registerSchemaInstaller(type, fn)` is called at module load time by adapter packages. The core `installSchemaFromString` dispatches to the registered handler. Importing `umzeption-pg` auto-registers the `pg` installer.

### Error Classes
Custom error classes are defined in `packages/umzeption/lib/errors.js`:
- `UmzeptionError` (base, with `.code`)
- `UmzeptionValidationError`
- `UmzeptionMigrationImportError`
- `UmzeptionUnsupportedContextError`

Use these instead of bare `new Error(...)` / `new TypeError(...)` for throw sites that match their semantics.

### Advisory Locks (pg)
`withAdvisoryLock` uses a **dedicated pool client** (not `pool.query()`) to ensure lock and unlock happen on the same connection. Supports `lockTimeoutMs` option via `SET lock_timeout`. Unlock is best-effort (PG auto-releases session locks on disconnect).

### SQL Parser (pg)
`splitStatements` is a **single-pass** state machine that strips comments AND splits on semicolons simultaneously, respecting single-quoted string literals. Does not currently support dollar-quoted strings (`$$...$$`) — this is a known limitation.

### Storage
`BaseUmzeptionStorage` supports configurable `tableName` with SQL injection prevention via regex validation. The `#tableEnsured` flag is set **after** successful table creation (not before).

### Migration Resolution
`resolveMigrations` in the core package:
- Uses `fs.glob` (Node 22+) with automatic fallback to `readdir`-based glob for Node 20
- The `fs.glob` import uses dynamic `import()` to avoid ESLint `n/no-unsupported-features` errors
- Supports `timeout` option via `withTimeout` (Promise.race + clearTimeout in finally)
- Validates migration names (no `|` or `:`), detects duplicates, provides ESM import hints

## Testing Conventions

- Test framework: `node:test` (built-in) + `assert/strict`
- Mocking: `sinon` for stubs (restore in `afterEach`)
- PG tests stub `pg.Pool.prototype.connect` or `.query` — no real DB needed for unit tests
- Integration tests requiring a real PG instance check for `PG_*` env vars
- Test files: `test/*.spec.js`
- Type contract tests: `tstyche` in `typetests/*.tst.ts`

## Related Packages

- **`@voxpelli/pg-utils`** — downstream consumer of umzeption for test DB lifecycle. It imports `createUmzeptionPgContext` and `pgInstallSchemaFromString` from umzeption (needs updating to import from `umzeption-pg` post-monorepo split)

## Common Commands

```sh
npm install                           # Install all workspace deps
npm run build                         # Build .d.ts declarations
npm run check                         # Full check suite (tsc + lint + knip + type-coverage)
npm run test                          # Run all tests
npm run check --workspace=packages/umzeption      # Check single package
npm run test:node --workspace=packages/umzeption-pg  # Test single package
```

## File Naming Conventions

| Pattern | Purpose |
|---------|---------|
| `*-types.d.ts` | Hand-authored type declarations (preserved by clean script) |
| `*.d.ts` | Generated declarations (deleted by clean script) |
| `advanced-types.d.ts` | Core type definitions (context registry, storage interface) |
| `pg-types.d.ts` | PG adapter types + module augmentation |
| `test/*.spec.js` | Test files |
| `typetests/*.tst.ts` | Type contract tests (tstyche) |
| `scripts/clean-declarations.js` | Cross-platform .d.ts cleanup |
